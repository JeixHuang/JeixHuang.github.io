1. Why Native HTML First 1. 为什么原生 HTML 是一等公民

Short research notes, open-source experiments, and interactive demos often lose clarity when forced through rigid Markdown shortcodes. In this unified Blog pipeline, every entry lives in its own folder under content/posts/<slug>/, and index.html renders verbatim without mangling inline <svg>, <canvas>, <video>, GIFs, or scoped scripts. 许多研究笔记、开源实验与交互演示一旦硬塞进受限的 Markdown 短代码，就会失去表现力。在这套统一的 Blog 构建管线中，每篇文章独立存放在 content/posts/<slug>/ 目录下，index.html 会原样直出，不会破坏内联 <svg>、<canvas>、<video>、GIF 动图或局部交互脚本。

Meanwhile, the outer layout keeps the author rail anchored on the left, centers readable prose at a quiet 740 px measure, and mounts a scroll-spy table of contents plus an optional companion X post card on the right. 与此同时，外层版式始终保持左侧个人栏吸顶、中间 740 px 静谧阅读宽，并在右侧自动挂载随滚动位置平滑追踪的滑动目录与可选的对应 X 帖子联动卡片。

4.1 Branch-Conditioned Score Objective 4.1 分支条件得分目标

Consider a trajectory $\tau = (s_0, a_0, \dots, s_T)$ branched from a saved checkpoint $s_k$. Comparing an unchanged continuation against a perturbed environment $E'$ yields a paired advantage estimate: 考虑从同一已保存检查点 $s_k$ 出发的分支轨迹 $\tau = (s_0, a_0, \dots, s_T)$。将保持原样与引入变化 $E'$ 后的续写配对比较，可写出如下局部优势估计：

$$\Delta_k(\pi) = \mathbb{E}_{\tau \sim \pi(\cdot \mid s_k, E')}\!\left[R(\tau)\right] - \mathbb{E}_{\tau \sim \pi(\cdot \mid s_k, E)}\!\left[R(\tau)\right]$$

4.2 Controlled Gradient Variance 4.2 可控梯度方差界

Coupling both continuations at checkpoint $s_k$ cancels prefix variance before intervention step $k$, isolating adaptation error strictly to post-shift decisions: 在检查点 $s_k$ 处耦合两条续写轨迹，可抵消干预步 $k$ 之前的前缀方差，将适应误差精确隔离到变化发生之后的决策阶段：

$$\operatorname{Var}\!\left(\hat{\Delta}_k\right) = \operatorname{Var}(R') + \operatorname{Var}(R) - 2\,\operatorname{Cov}\!\left(R', R \mid s_k\right)$$

6. Syntax-Styled Code & Booktabs Tables 6. 轻量着色代码块与 Booktabs 学术表格

Code blocks sit on a warm archival surface with a quiet top bar and one-click copy. Optional mineral token spans (.tok-kw, .tok-fn, .tok-str, .tok-num, .tok-cm) provide crisp syntax hierarchy with zero third-party JS dependencies: 代码块采用微暖纸面与极简顶栏一键复制，可选内置矿物色语法标记类（.tok-kw / .tok-fn / .tok-str / .tok-num / .tok-cm），无需引入外部高亮库： 

def paired_continuation_delta(baseline, shifted):
    """Compute checkpoint-coupled adaptation shift."""
    assert len(baseline) == len(shifted), "Mismatched rollout count"
    diffs = [s - b for b, s in zip(baseline, shifted)]
    return sum(diffs) / max(1, len(diffs))

8. Three-Step Publishing Workflow 8. 三步发布新博文工作流

8.1 Metadata & Artwork 8.1 元数据与卡片艺术

Start every HTML post with a JSON <!--meta { ... } --> block (or a sibling meta.json). Keep "draft": true while iterating locally, and flip it to false only when ready to publish. 每篇 HTML 文章顶部写入 JSON 格式的 <!--meta { ... } --> 注释块（或同目录放 meta.json）。本地打磨阶段可设为 "draft": true，准备公开时再改为 false。

8.2 Companion Assets & Verification 8.2 伴生素材与自动校验

Drop figures, GIFs, MP4 clips, or JSON logs directly next to index.html inside the post folder, then run python3 scripts/build.py && python3 scripts/check_site.py _site to verify every internal link, anchor, DOM ID, and draft boundary. 将图片、GIF、MP4 短片或 JSON 数据放在文章目录的 index.html 旁，随后执行 python3 scripts/build.py && python3 scripts/check_site.py _site 校验全部内链、锚点、DOM ID 与草稿边界。
